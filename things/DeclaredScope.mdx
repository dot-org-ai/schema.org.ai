# DeclaredScope

DeclaredScope is the **scope axis** of an [AutonomyClaim](AutonomyClaim.mdx): the declared operational domain within which the claimed [AutonomyLevel](AutonomyLevel.mdx) holds. It is derived directly from [SAE J3016](https://standards.org.ai/SAE/J3016#ODD)'s **Operational Design Domain (ODD)** — the conditions under which the automation is designed to function — carried from driving conditions to business verbs.

## Definition

- The scope is declared **per verb**, not per brand. A scope names the verbs (or verb families) the system owns and the regime it owns them in — e.g. `{data, sim, grade, paper}` with live execution excluded.
- **Exclusions are typed as walls.** A scope exclusion is a [DoctrineWall](DoctrineWall.mdx), and per R12-2 **the wall list and the DeclaredScope exclusions are one object read twice** — scope and tier are not independent coordinates. Removing an exclusion is a wall-removal, and therefore a re-tiering event.
- **Scope-exit triggers the MRC.** Leaving the declared scope is not an error state; it is the defined transition into the [MinimalRiskCondition](MinimalRiskCondition.mdx), which must be machine-reachable and duty-preserving.
- The claim attaches to declared scopes, not the brand: a company whose product serves L4 customers may itself operate L2/L3 owner-gated loops on other scopes.

A per-verb authority ladder (each verb individually granted, bounded, and revocable) is a DeclaredScope in operational form — per-verb ODD declaration on a live object.

## Example

```typescript
const scope = {
  $type: 'DeclaredScope',
  name: 'kestrel market-data scope',
  includes: ['data', 'sim', 'grade', 'paper'],
  excludes: [
    {
      $type: 'DoctrineWall',
      name: 'no-live-execution-without-covenant',
      description: 'Live/broker verbs excluded behind human-signed covenant-verbs',
    },
  ],
}
```
